# 架构与研发路线

## v0.1：当前实现

静态 HTML + CSS + 原生 JavaScript ES Modules，无前端构建依赖。Node.js 只承担本地开发、测试、静态复制和源码打包，浏览器运行时不需要 Node。

`courses.js` 管理课程、知识点、依据、提示与评分规则。`app.js` 通过 hash 路由渲染页面，维护每个知识点的一次练习状态。`storage.js` 校验和保存 localStorage 数据，读取损坏数据时安全回退。

流程：选择知识点 → 记录思路 → 主动请求提示或解析 → 小测 → 生成记录 → 再次练习。

单次记录包含题目 ID、选项、是否正确、最高提示级别、是否看过解析、当时的思路及 ISO 时间。完成后该次练习锁定，重新练习会重置会话，但保留旧结果。来源解释、评分与复练建议均为规则结果，无模型调用。

使用提示或解析后答对会标记为辅助完成；未用提示/解析答对只表示本次独立作答表现，不等同于掌握。记录可导出但暂不提供导入或云端同步。

## 下一阶段

1. 按 `materials.md` 整理并核验小规模课程包。
2. 增加 FastAPI 服务，使用 SQLite 保存资料版本、会话、尝试与小测结果。
3. 引入课程与资料版本隔离的检索，并校验引用 ID、原文位置及支撑关系。
4. 通过后端模型适配层生成追问与解释，后端校验允许的动作和提示级别。
5. 小测评分维持可复现规则；无法可靠判断的开放答案标记待复核。
6. 建立独立开发、评测和试用数据，记录失败案例，检验学习效果。

## 接口方向（计划，未实现）

- `GET /api/courses` 与 `GET /api/courses/{id}/topics`
- `POST /api/sessions` 与 `POST /api/sessions/{id}/attempts`
- `POST /api/sessions/{id}/hints`
- `POST /api/sessions/{id}/quiz`
- `GET /api/evidence/{id}` 与记录导出接口

正式服务应增加身份与访问控制、授权资料管理、调用限额和日志最小化。模型密钥不放前端；原始资料与学生隐私数据不进入静态发布包。C 语言任意代码执行需要独立隔离环境，当前未实现。
